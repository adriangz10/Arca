Armar un bot de WhatsApp para facturar en Argentina es una solución excelente porque reemplaza una interfaz engorrosa (la web de ARCA) por un mensaje de texto o un audio de 5 segundos: "Facturale $45.000 a Consumidor Final por servicio de diseño" o "Haceme una factura A al CUIT 30-71234567-9 por $120.000 más IVA de mantenimiento".El secreto arquitectónico para que esto sea sólido y no falle nunca es una regla de oro: la IA (LLM) solo extrae intenciones y parámetros; el cálculo matemático, las reglas fiscales y la comunicación SOAP con ARCA deben ser 100% determinísticos en el backend.1. Capa de Entrada y Extracción Multimodal (El "Cerebro" Conversacional)El usuario no quiere llenar un formulario; quiere mandar un audio mientras maneja o reenviar un comprobante de transferencia de Mercado Pago.Procesamiento de entrada: Si entra un audio (.ogg) o una imagen (captura de transferencia o foto de un CUIT), se pasa directamente a un modelo multimodal rápido y económico (como Gemini 2.5 Flash).Structured Outputs / Tool Calling: En lugar de que la IA responda texto libre, se la configura para rellenar un esquema JSON estricto (DraftInvoiceSchema):JSON{
  "accion": "EMITIR_FACTURA",
  "monto_total": 45000,
  "moneda": "PES",
  "receptor_documento": "20345678901", // o null si es Consumidor Final anónimo
  "concepto_descripcion": "Honorarios por desarrollo web",
  "tipo_concepto_arca": 2, // 1: Productos, 2: Servicios, 3: Ambos
  "iva_incluido": true
}
Máquina de Estados (Session Memory en Redis): Si el usuario dice "Facturale 50 mil a Juan" pero falta el CUIT o el concepto, el bot guarda el borrador parcial en Redis (con un TTL de 15 minutos) bajo el número de teléfono del usuario y repregunta solo el dato faltante.B. Enriquecimiento Automático y Validación Pre-Vuelo (Sin pedirle datos de más al usuario)Para que sea "sencillo", el usuario nunca debería tener que decir si la factura es A, B o C. Tu backend lo resuelve solo:Autodetección de Comprobante:Tu base de datos ya sabe qué es tu usuario emisor (ej. Monotributista -> siempre emite Factura C).Si tu usuario emisor es Responsable Inscripto y pasa un CUIT del cliente, tu backend consulta en milisegundos el padrón de ARCA (ws_sr_constancia_inscripcion_v5).El padrón devuelve el nombre real de la empresa/persona y su condición frente al IVA. Si el receptor es RI o Monotributista -> tu backend selecciona automáticamente Factura A; si es Exento o Consumidor Final -> selecciona Factura B.Regla del Tope de Consumidor Final ($10.000.000):Si el usuario dice "Facturá 15 mil pesos a Consumidor Final", el bot ni siquiera le pide DNI (manda DocTipo: 99, DocNro: 0).Si el monto supera el tope legal vigente (o si el usuario aclara que el cliente quiere deducir Ganancias), el validador frena el flujo y el bot pide por WhatsApp: "Por el monto, ARCA exige DNI o CUIL del comprador. Pasámelo por acá."Paso Obligatorio de Confirmación (Human-in-the-loop):Recordá que en ARCA una factura emitida no se puede borrar (habría que emitir una Nota de Crédito para anularla).Antes de tocar el WSFEv1, el bot envía un mensaje con Botones Interactivos de WhatsApp:📄 Resumen para emitir:• Tipo: Factura C (Servicios)• Cliente: JUAN PÉREZ (CUIT 20-34567890-1)• Concepto: Mantenimiento mensual• Total: $45.000,00[ ✅ Emitir ahora ]  [ ✏️ Corregir ]  [ ❌ Cancelar ]C. Gestión de Certificados y Tokens WSAA (Caché en Redis)Si este bot lo vas a usar solo para vos (Single-Tenant), guardás tu .crt y .key en variables de entorno/secretos. Si lo pensás como un SaaS para múltiples clientes (Multi-Tenant), no hace falta que cada cliente genere certificados con OpenSSL: ellos simplemente entran a su ARCA y delegan el servicio "Facturación Electrónica" al CUIT de tu plataforma (o suben su certificado a tu sistema encriptado en base de datos con AES-256).Manejo del Token de 12 horas: Cuando se necesita hablar con ARCA, tu servicio ArcaAuthService primero busca en Redis la clave arca:ta:{cuit_emisor}.Si existe y no expiró, usa ese Token y Sign.Si no existe, llama a WSAA, obtiene el Ticket de Acceso nuevo y lo guarda en Redis con un TTL de 11 horas y 50 minutos (para evitar problemas de sincronización de relojes justo al límite de las 12h).D. La Cola Secuencial (El problema de concurrencia de ARCA)Este es el punto técnico donde fallan el 90% de las integraciones caseras con ARCA.
Para emitir una factura con FECAESolicitar, ARCA te exige que le envíes qué número de factura es (consultando antes FECompUltimoAutorizado y sumándole +1).¿Qué pasa si entran dos mensajes al mismo segundo para el mismo Punto de Venta? Ambos leen que la última factura fue la 100, ambos intentan emitir la 101, y ARCA rechaza una con error de numeración o duplicidad.Solución en la Arquitectura: Cuando el usuario presiona [ ✅ Emitir ahora ], el pedido entra a una cola en BullMQ (Redis) agrupada por CUIT + PuntoDeVenta con concurrencia = 1 (o usando un Distributed Lock / Redlock).Toma el bloqueo del Punto de Venta.Consulta FECompUltimoAutorizado (ej. 100).Arma el payload XML/SOAP para la factura 101 (calculando Neto + IVA exactos al centavo y agregando la transparencia fiscal si es Factura B).Llama a FECAESolicitar y recibe el CAE.Guarda en tu base de datos PostgreSQL el comprobante autorizado y libera el bloqueo. Todo toma menos de 1.5 segundos.E. Generación del PDF Oficial y el Código QR de ARCAUna vez que FECAESolicitar devuelve "Resultado": "A" y el número de CAE, ARCA no te devuelve un PDF; solo te devuelve datos en XML. El PDF o ticket lo tenés que dibujar vos en tu servidor.Armado del QR Oficial: Según la RG 4892, tenés que armar un objeto JSON con 13 campos exactos (versión, fecha, cuit, ptoVta, tipoCmp, nroCmp, importe, moneda, ctz, tipoDocRec, nroDocRec, tipoCodAut: "E", codAut: CAE), convertir ese JSON a Base64, y concatenarlo a la URL:[https://www.arca.gob.ar/fe/qr/?p=](https://www.arca.gob.ar/fe/qr/?p=){BASE64_AQUI}Renderizado de la Imagen QR y el PDF:Con una librería liviana como qrcode en Node.js generás el código QR en DataURL (PNG).Inyectás los datos de la factura + el QR en una plantilla HTML/CSS limpia (podés ofrecer dos formatos: A4 tradicional o Ticket térmico de 80mm ideal para leer en el celular).Con Puppeteer, Playwright o un generador directo como PDFKit / Typst (mucho más liviano en memoria RAM que levantar un navegador headless), generás el binario del PDF.Entrega en WhatsApp: Enviás el PDF directamente por la API de WhatsApp como un documento adjunto (document message) con el nombre Factura_C_00002-00000101.pdf.3. Detalles de UX (Experiencia de Usuario) que hacen la diferencia en WhatsAppSi querés que el bot se sienta realmente mágico en el día a día:Facturación desde Comprobante de Pago (OCR): Que el usuario pueda reenviarle al bot la captura o el PDF de una transferencia que acaba de recibir (de Mercado Pago, Brubank, banco, etc.). El modelo multimodal lee el importe exacto y el CUIT/CUIL del pagador de la imagen, consulta el nombre en el padrón de ARCA y le pregunta directo: "Detecté una transferencia de $32.500 de María Gómez (27-12345678-4). ¿Le emitimos la factura por ese monto?"Anulación en 1 clic: Si el usuario responde (cita/reply) al mensaje del PDF que el bot le acaba de mandar y escribe "Anulala, me equivoqué de monto", el bot lee el message_id citado, busca en la base de datos qué factura era (0002-00000101), y automáticamente arma y emite la Nota de Crédito vinculada a ese comprobante sin que el usuario tenga que tipear ningún número.Alertas de Tope de Monotributo: Como todas las facturas pasan por tu base de datos, después de emitir cada comprobante el bot puede sumar la facturación acumulada de los últimos 365 días y avisarle: "Factura emitida.
